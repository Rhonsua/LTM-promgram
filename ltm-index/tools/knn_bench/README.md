# 固定工作量 KNN 读者测量

在工程根目录执行：

```text
python -B scripts/knn_bench.py
python -B scripts/knn_bench.py --profile asan --quick
python3 -B scripts/knn_bench.py --profile tsan --quick
python -B scripts/knn_bench.py --audit <本轮证据目录>
```

TSAN 在 Linux / WSL 内执行。各轮默认新建构建和证据目录；可用 `--build-dir`、
`--output` 指定工程内尚不存在的目录。`--skip-build` 仅复用指定程序，不构成新的
编译证明；正式结果使用新目录完整构建。主工程与原有 `ltm_bench` 协议保持原样。

普通完整矩阵使用 1,024 条二维记录、4,096 次查询、256 次预热；k 为 1/16/64，
读者为 1/2/4，16 帧与 256 帧各三次，共 54 次测量。固定随机顺序执行各单元，
每次从独立新库装载、检查点和关闭开始，然后由新进程测量，再由另一个新进程
重开、校验完整记录和全部查询。不同读者数分摊同一批总查询，按查询编号轮转
分配，不能把每个读者执行完整负载后增加的工作量误认为吞吐提高。

`--quick` 是 512 条记录、48 次查询、32 次预热、1/4 读者、12/128 帧的一次重复
矩阵，共 12 次；用于程序正确性，不计算可靠提速比。ASAN / TSAN 强制使用该模式，
其时间只能作运行记录。工具自身限制记录、操作、线程数及保留答案的数量。

计时前独立枚举数据计算点到矩形距离，以 `(sqrt(距离平方), 键)` 完整排序构造
参考答案，不调用索引距离和候选选择函数。等距探针故意产生边界同距记录。
所有线程共同等待开始信号，完成后按原查询顺序核对每一项键、完整 MBR 和载荷；
参考计算与校验均在计时外，答案一直保留到核对结束。计时区间不逐查询获取统计。

墙钟从主线程发出开始信号前到最后一个读者完成，包含唤醒调度、计时、状态检查
和循环记账，不含创建线程、参考计算、结果校验及等待线程退出的 join。API 延迟
包含 Knn 返回结果的物化，逐查询预留结果向量容量，但记录自身仍按真实 API 分配。
延迟分位使用 nearest-rank；多线程 API 耗时之和不能当作墙钟。结果额外保留造成
的内存成本属于测量工具，不代表引擎的页工作集已经超过系统可用内存。

重开后先 Validate 并完整遍历数据库，再读取结构页数及执行固定预热。页数由
Validate 填充，不用重开后尚未填充的零页统计。全驻留要求双树加元数据页不超过
帧数，且测量期实际页读/淘汰均为零；淘汰要求 R 树加元数据页已超过帧数，且测量
期实际读页和淘汰均非零。测量期查询数必须等于总操作数，逻辑写、页写、WAL 追加
和脏页淘汰都必须为零。缺页读为 DiskManager 的文件页请求，可能命中系统缓存，
不能称为冷设备或物理磁盘访问。预热中保留实际页热度策略；不关闭热度来避开竞争。

驱动在每种配置实跑 10 项协议/CLI 测试，保存源码快照、编译参数、程序哈希、
每阶段原始输出与退出码、最终数据库/WAL 哈希以及三次重复的最小值/中位数/最大值。
审计重新解析原始输出，核对每个矩阵单元和重开结果，重建摘要并检查全部保存文件。
TSAN 还实跑有竞争/加锁对照并核对运行库符号，ASAN 检查运行库导入，二者均核对
所有编译单元插桩。本工具不替代核心全量回归、长压测和强杀恢复矩阵。
