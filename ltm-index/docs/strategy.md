## 3. 并发对照不能只加 seed

同种子不能固定线程调度；多写线程更新同一键的顺序不同，合法的最终结果也可能不同。
按操作次数生成固定操作流，避免以运行秒数决定比较样本。

第一阶段使用互不相交的写键空间，每个键由一个写线程按固定顺序更新，所有输入预先生成；
单线程重放同一输入，多线程结束后比较完整键、MBR、payload，而不只比较条数或哈希。
读线程查询单独的不可变键集，逐次检查完整载荷；每轮执行树不变量与 I8 双向交叉校验。
这样同时获得真实并发执行和确定的参考结果。

第二阶段若需覆盖同键冲突和读写重叠，使用受控阶段屏障，或记录操作调用/返回区间并
检查是否存在合法串行历史。不得让一次读必须等于最终值，也不得把强制串行运行当并发证据。
吞吐压测与上述对照各有用途，分别保留。

## 4. 热度路径的最小修复原则

先列出 Touch、Heat、DecayAll、页分配/释放、回滚及 stats 的共享状态和调用锁范围。
优先在 HotColdTracker 自身形成完整同步边界；若采用互斥锁，任何回调不得在持热度锁时
反向调用 BufferPool 或取页闩。逐项写清与页闩、帧表锁的顺序及对象生命周期。
不能仅给 Touch 加锁而遗漏 Heat/DecayAll 或容器扩容；也不能用关闭热度掩盖启用配置的问题。
同时核对 HybridIndex 的组合读写可见性，尤其是跨两棵树的 Query/Knn/Validate。
后台衰减和主动刷脏页延后到同步边界明确之后。

P1 实现采用完整逻辑操作的读写门：读者可重叠，写入、关闭、检查点及校验排他；
2026-10-08 起 KNN 计数已改为调用内累积、结束后短锁发布，撤去额外整段串行。
范围/空间扫描回调复制一页结果、释放页闩后执行；KNN 在结果缓冲中持有载荷。
允许同索引嵌套读取，拒绝读回调升级为写操作。显式 DecayHeat 提供并发衰减入口，
热度表自身保护全部共享状态。详细锁顺序与对象生命周期见 architecture.md。
长压测分别保留持续 crabbing 历史和启用热度的有界重复轮次，不能把后者写成同一个
数据库持续 30 分钟的操作历史。P2 查询闭环已完成其限定范围，尚未用这些并发正确性数据形成性能结论。

Windows MSVC 无 TSAN；2026-10-07 已补 WSL2 Ubuntu + Clang 21 环境，并证明
TSAN 能检测真实竞争。验收入口 scripts/accept_tsan.py，先执行运行库正反对照，
再完整构建、检查插桩、执行全量普通测试和两棵树守门、跨进程链路，保存原始输出。
Windows 普通与 ASAN 另行回归。完整证据通过前不勾选数据竞争检测；通过后也仅
覆盖实际执行的 API、负载和配置，不能据此宣称任意调度或跨线程锁环均已排除。
