Windows 普通/ASAN 全量与 Linux TSAN 受影响路径通过，独立复核 `audit.json` 为 passed。

## 复跑

在 `ltm-index` 目录先构建，再执行驱动：

```powershell
python scripts/build_local.py build build-ninja
python scripts/mixed_bench.py
```

默认初始 512 条二维记录、300 次测量操作、种子 42、30 次预热 Get，12/128 帧各三轮。
每轮新建数据库，完整验证后保存检查点并关闭，再启动新进程重开同一数据库验证。
输出目录默认带时间戳，已有目录拒绝覆盖；成功显示 `MIXED_VERDICT: passed`。
内存检查版本需先构建 `build-asan`，驱动使用 `--build-dir build-asan`。

```powershell
python scripts/mixed_bench.py --records 1024 --ops 1000 --frames 12 256 --repeats 3
python -m unittest discover -s scripts -p 'test_*.py'
python report/bench/mixed/verify.py
```

最后一条复核的是本次固定路径下的最终证据；其源码或二进制版本不匹配时明确失败。
`accept.py` / `accept_linux.py` 是本轮验收入口，固定输出目录已有证据后拒绝重复写入。
需再次完整验收时为新轮次选择新的输出目录，保留旧证据。

## 负载和校验

每 100 次操作严格包含 Get 35、range 15、spatial 10、contain 5、KNN 5、Put 15、Erase 15。
操作数只接受整百；初始记录限制 32–20000，测量操作限制 100–100000。
独立 map 预先生成操作顺序、键、MBR 与载荷，实际执行结果不改变后续输入。
记录条数始终在初始条数的 50%–125% 内；每块固定覆盖删除重插、更新和不存在键删除。
其余操作按确定种子洗牌，输入与最终逻辑记录分别保留四个指纹。

每次读核对完整 key/MBR/payload 与独立参考；每次写后进行单独 Get 探测。
末尾检查全量有序扫描、所有有界键的存在/缺失、空间/包含/KNN、结构及双向 I8。
重开阶段的校验区间必须零逻辑写入、零 WAL 追加、零页写入；打开/关闭的日志头维护
在此区间之外。两棵树条数及 I8 对数必须等于最终 map 条数。

结果前缀为 `MIXED_RESULT`，与只读 `BENCH_RESULT` 的 schema 分开。
驱动独立重放键集合，校验写入语义、每类数量、成功/未找到数、所有计时/计数加和。
缺字段、错误指纹、零测量、错误退出、已有数据库、未知选项、真实超时均不能生成成功结论。
参考测试另外覆盖稀疏键、重复/遗漏/错误载荷、KNN 距离边界及长操作流的数据条数下界。

## 测量边界

每次 API 的计时与 13 项计数单独采样；写后探测的计时和计数另列。
原始 `samples` 可重算每类 p50/p95/p99、API/探测/测量期 I/O、两种吞吐口径。
参考计算、统计快照、装载、预热、末尾验证、末尾检查点分别处于明确的阶段。
末尾检查点产生的写入不能充当测量期 WAL/脏页淘汰证据。

驻留按整个轨迹的物理页地址上界保守证明，并要求测量期间零淘汰。
淘汰要求帧数小于初始双树工作集，且 API 测量区间实际有页读及淘汰。
中间配置拒绝用于对照；不能把总页读冒称每类查询都访问了磁盘。
计数表示应用层逻辑页/WAL 请求，不能解释为设备物理 I/O。

探测会改变后续缓存状态；本版提供带逐次校验的固定轨迹观察。
其吞吐不能用于无探测的性能结论、缓存策略优劣或不同检查器间的性能比较。
后续性能对照需在独立数据库上分离正确性轨迹和测量轨迹。
