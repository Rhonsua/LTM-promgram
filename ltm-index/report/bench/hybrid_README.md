# P2 Hybrid 空间/KNN 基准（2026-10-07）

已接入 `spatial`（闭边界相交）、`contain`（完整矩形包含）和 `knn`，沿用
独立运行目录、固定输入、逐次结果核对、分阶段计时、JSON/CSV 与严格驱动校验。
本轮只改基准、驱动和参考判据测试；45 个既有索引/存储/热度/并发源码文件与
P2 B+ 版本逐项哈希一致。M6-3 全部负载和 P3 大规模实验仍未完成。

## 复现

```text
python scripts/build_local.py build build-ninja
python scripts/build_local.py build build-asan
python scripts/test_bench.py
python scripts/bench.py --workloads spatial contain knn --records 1024 --ops 500 --frames 12 256 --repeats 3
```

空间窗口宽度默认 8、KNN 默认 k=10，可用 `--spatial-width`、`--knn-k` 调整。
两者均须为正整数，k 不超过记录数。独立程序同样支持这些参数；已有数据库
退出 2 且不修改文件。每次驱动运行必须使用新输出目录。

验收脚本 `report/bench/accept_hybrid.py --output-dir 新目录` 自动配置 ASAN 运行库
路径，并保存负向参数、普通/ASAN 对照、测试和结构守门的原始输出。
默认目录 `hybrid_acceptance/` 已存在，会拒绝覆盖。ASAN 对照直接运行时需要
MSVC 开发者环境，以便找到 ASAN DLL；构建缓存启用了 `/fsanitize=address`，
`asan_imports.txt` 额外确认最终基准程序导入 ASAN 运行库。

## 查询与测量契约

- 单线程、4KB、双树容量均为 32、二维矩形、R 树 quadratic 分裂、预取关闭。
  HybridIndex 实际注入 HotColdTracker 和 MigrationPolicy，报告明确记录
  `heat=enabled, policy=migration`；B+ 仍为 `heat=none, policy=clock`。
  每个引擎内部只比较池帧数，不能把两种引擎间的差别解释为纯缓存策略收益。
  本轮没有后台衰减、自动检查点或预取，也没有完成 migration 策略对照实验。
- 固定 seed=42、1024 条完整载荷记录，使用带细小偏移的网格矩形和独立查询流。
  显式 Fisher-Yates 装载；数据指纹覆盖键、维度、MBR 和载荷，查询指纹覆盖
  实际坐标、顺序、查询类型与参数。每个参数组三次重复，输入指纹一致。
- 独立参考计算不调用生产 MBR 相交/包含/距离函数或树遍历。
  空间结果按完整集合核对，拒绝重复、遗漏、错误键、MBR 或载荷，不要求遍历键序。
  KNN 独立计算点到矩形的平方距离，核对数量、距离顺序、边界距离和完整记录，
  要求所有严格更近的记录出现；第 k 名距离相同时允许任意合法候选，
  不宣称当前实现会优先选择最小键。距离比较仅容许浮点舍入误差。
- 参考答案预先生成，记录 `oracle_seconds`，不纳入查询计时或测量 I/O。
  装载、Validate、检查点、全量记录核对及缓存填充后，进行 50 次查询预热。
  正式测量 500 次查询，结果物化/复制、清理以及调用接口的开销计入查询延迟；
  每次完整结果核对在该次计时外。吞吐按各次查询耗时之和计算，另记录含核对
  的测量循环墙钟时间。分位数沿用所有查询样本的 nearest-rank。
- `working_set_pages=106` 是双树 51+54 页加元数据页；`active_pages=55`
  是空间/KNN 路由所用 R 树加元数据页的保守页数。
  驻留必须池帧数覆盖双树总页数且实测缺页/淘汰均为 0；淘汰必须池小于
  R 树页集合且实测缺页/淘汰均非零。两者之间标为 `indeterminate`，驱动拒绝
  用于该对照。64 条记录、6 帧的真实负向案例确实零缺页，但被正确拒绝。
- I8 全量交叉核对 1024 对记录，测量前后结构校验通过；I6/锁序违反均为 0。
  测量统计来自一致快照的前后差值，只读 `page_writes=wal_bytes=0`。
  页读是应用逻辑 I/O，不代表物理设备读取或系统 RSS 超限。

## 最终结果

`hybrid_final_comparison/` 是验收结束后单独运行的最终对照，18 次全部通过。
此前 `hybrid_comparison/` 是初始样本；`hybrid_verified_comparison/` 是加入边界
样本后的首轮验证，部分时段与验收同时运行，均保留为开发证据，未用于下表。

| 查询 | 帧数 | 配置 | 吞吐中位数（次/秒） | p99 中位数（微秒） | 页读中位数 |
| --- | ---: | --- | ---: | ---: | ---: |
| 相交 | 12 | evicting | 18655 | 95.2 | 1334 |
| 相交 | 256 | resident | 92914 | 13.6 | 0 |
| 包含 | 12 | evicting | 21207 | 86.3 | 1334 |
| 包含 | 256 | resident | 202782 | 7.3 | 0 |
| KNN，k=10 | 12 | evicting | 13262 | 126.0 | 1608 |
| KNN，k=10 | 256 | resident | 43527 | 29.7 | 0 |

相交与包含的查询窗口包含部分交叠样本：500 次查询分别得到 4065 条和 571 条；
KNN 每轮固定 5000 条，所有结果经独立判据核对。
`summary.json` 记录 min/median/max，CSV 保留每次完整指标；样本和计时间隔较短，
这些数字只证明基准运行及路径差异，不能推广为论文级性能结论。

## 验收与复核

- `hybrid_acceptance/manifest.json`：19 项验收命令全部达到预期退出码；
  新负向参数、未知负载、已有库保护、模糊缓存配置拒绝均有原始输出。
- 普通全量 ctest **18/18（139.12 秒）**；ASAN 专项 **2/2（9.36 秒）**，
  覆盖 Hybrid 差分与新增参考判据测试。ASAN 专项不冒称本轮全量 ASAN ctest。
- ASAN 空间/包含/KNN 对照 **18/18**，512 条、200 次查询、8/128 帧，每组三次。
  B+ point/range 回归对照 **12/12**，相同规模与帧数。
- 参考判据两个用例覆盖闭边界、部分相交、包含、空集合、KNN 边界平局、
  全部 k，并故意提供遗漏更近记录、远点、逆序、重复、错误载荷/MBR 以证明拒绝。
  Python 协议测试 **8/8**，逐个删除新增必填字段并验证错误策略、I8、页数和 k。
- 两个结构守门退出 0，I6 违反 0；分层扫描 48 文件、ASCII 扫描 85 文件，均无违反。
- `hybrid_verification.json` 是第二次复核：重新检查 48 次最终/ASAN/B+ 运行的原始
  JSON、CSV、汇总、指纹、参数及源码/二进制哈希，核对 18+2 项测试日志和 ASAN
  DLL 导入，并实际逐项核对 45 个内核文件。入口为 `report/bench/verify_hybrid.py`。
  未重跑 C1 长压测、完整 ASAN 套件或 TSAN；本轮索引内核没有变化。
