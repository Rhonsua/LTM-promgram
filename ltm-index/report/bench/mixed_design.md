# 固定操作流混合读写：第一版实施约定

依据 docs/status.md、docs/strategy.md 和已完成的 B+/Hybrid 基准。Linux TSAN 与回滚修复
验收已完成。2026-10-07 本文件约定的第一版已实现并通过验收，入口、实测与限制见
[混合基准说明](mixed/README.md)；本文保留设计，实际证据以该目录的原始输出与 audit.json 为准。

## 第一版范围

使用现有 HybridIndex、4KB 页、二维 quadratic R 树、单线程和实际热度/迁移策略。
只增加一种固定、有界的 mixed 负载；不同时扩大到多线程、后台任务、不同页大小。
每 100 次操作固定包含 Get 35、range 15、spatial 10、contain 5、KNN 5、Put 15、Erase 15，
按种子预先确定次序、键、MBR 和载荷。不足整块的操作数明确拒绝，不能靠随机比例漂移。
Put 覆盖新键和已有键改 MBR/载荷；Erase 覆盖存在键、不存在键和删除后重插。
流生成基于独立 map 模型，不根据实际索引结果临时改变后续操作。

输入分别记录初始数据、操作流及查询参数指纹；数据量上界固定为初始条数的 125%。
每轮使用独立数据库，先装载/预热，再执行操作流，再完整扫描及双向 I8 校验。
固定初始 512 条、300 次操作起步；普通与 ASAN 的驻留/淘汰配置每组至少三次。

## 校验与测量边界

map 持有完整 key/MBR/payload。每次读返回完整记录与独立参考集合逐条核对；
范围按键过滤，空间与包含复用独立几何参考，KNN 沿用严格的距离边界判据。
每次 Put 后定点读取核对新记录；每次 Erase 后确认目标缺失；失败或缺字段立即失败。
末尾全量记录必须与 map 相等，检查重复、遗漏、多余及载荷错误，再执行 Validate/I8。

API 调用计时排除参考计算及探测校验。按操作类型记录调用数、成功/未找到数、
延迟分布及调用前后 Pool/IoStats 差值；校验探测产生的页读写另列，不能混进 API 指标。
所有计时总和、每类计数及 I/O 差值必须可由原始结果重算。快照、参考计算及校验耗时
也单独记录；全过程墙钟与 API 计时合计分别报告，不能互换吞吐口径。

校验探测会改变后续缓存状态，因此首版结果是带探测的固定操作流观察，不能宣称
无探测的混合负载性能或策略优劣。后续性能实验先增加独立正确性轨迹与测量轨迹，
在新库重放同一输入，再讨论缓存策略对照。

## 结果协议

使用新 schema，保留现有只读 schema 及其零写入判据。mixed 的末尾条数可变，
I8 对数须等于最终 map 条数；初始条数、最终条数、成功 Put/Erase 数分别记录。
每类操作数量之和必须等于声明 ops；缺失操作类型、零测量、错误退出或坏指纹拒绝。
混合测量须有真实 WAL 字节增量；页面写入可由脏页淘汰产生，不能通过无关的末尾
检查点伪造测量期写入。末尾检查点及其 I/O 单独列示，正向链路另验证新进程重开。

驻留配置依据操作流的完整工作集上界，验证测量期间无淘汰；淘汰配置须有真实缺页/
淘汰，并区分哪些由读取、写入或校验探测造成。工作集变化及新页分配单列，不能
把初始页数直接当整段轨迹的峰值，也不能把整体缺页冒称每种查询都触发了磁盘访问。
所有 I/O 指标指应用逻辑页/WAL 请求，不冒称设备物理 I/O。

## 退出条件

1. 普通/ASAN 各六次固定轨迹全部正确，同参数指纹和最终完整记录一致。
2. 已有只读基准协议保持通过；新 schema 对缺字段、错计数、坏指纹、错误载荷、
   已有库路径、未知负载和超时有真实负向验证。
3. 当前全量测试、结构守门、分层和 ASCII 检查通过；未改页闩或接口门时不重复长压力。
4. 原始参数、输出、源码/二进制版本和重复分布齐全，status 仅勾选该限定范围。

完成后再扩大数据/负载，接检查点与恢复曲线和 M7 报告。
