# KNN 固定总工作量与多读者测量（2026-10-16）

本轮补齐当前磁盘页式版本的 KNN 测量入口与限定矩阵，未修改引擎核心。
最终普通 **54 次测量 + 54 次新进程重开**，ASAN 与 Linux TSAN 各 **12 + 12**，
合计 **78 + 78** 均通过；每种配置实跑 **10 项协议测试**。独立核对另补每配置
7 个替换单项参数的真实负向调用，共 21 项，避免只测重复参数而漏测实际边界。
结题材料保持原样。

## 结果与范围

普通配置：1,024 条二维记录、4,096 次固定查询、256 次预热；二维 quadratic R 树，
B+ / R 容量均为 32，4KB 页，实际页热度策略、关闭预取。读者为 1/2/4，k 为
1/16/64，16/256 帧各三次，独立新库、固定打乱单元顺序。所有读者完成的是同一批
总查询。三次重复的最小值/中位数/最大值及 p50/p95/p99 见
[完整 CSV](ordinary/summary.csv) 与 [JSON](ordinary/summary.json)。

下表为墙钟查询吞吐的三次中位数（查询/秒），仅描述本轮有界负载：

| 页驻留状态 | k | 1 读者 | 2 读者 | 4 读者 |
| --- | ---: | ---: | ---: | ---: |
| 全驻留，256 帧 | 1 | 123,068 | 199,364 | 266,002 |
| 全驻留，256 帧 | 16 | 29,398 | 53,118 | 104,498 |
| 全驻留，256 帧 | 64 | 9,830 | 17,396 | 36,496 |

驻留场景增加读者能提高本轮吞吐；频繁淘汰时则没有形成稳定扩展收益。后续应先
定位缺页/淘汰路径中的锁等待与文件页请求成本，再决定优化位置。该矩阵不能单独
把瓶颈归因到某一把锁，也不能用于计算候选堆相对旧实现的提速比例。

全驻留测量期读页与淘汰全部为零；淘汰配置的 R 树加元数据页实际超过帧数，测量
期读页和淘汰均非零。所有测量期逻辑写、页写、WAL 追加、脏页淘汰均为零，查询
计数严格等于固定总操作数。实际缺页数随并发调度变化，不能强求不同读者数的
页读计数相同。文件页读可能命中系统缓存，不等于设备物理 I/O。

## 测量与正确性边界

先在独立进程装载、完整校验、检查点和关闭；再由新进程完整校验已有库，补齐
Validate 才会生成的结构页数、执行预热，才启动计时。参考模型枚举全部记录，
独立计算点到矩形的距离并按 `(距离, 键)` 排序；探针包含等距边界。结果保留到
计时结束，按固定查询序逐项比较键、完整 MBR 和载荷，随后再次检查双树不变量。
最后用另一个新进程校验全部持久化记录和所有查询，并匹配有序答案指纹。

墙钟包括同步唤醒、调度、状态检查和循环记账；API 延迟包括 Knn 及结果物化，
参考计算、校验和统计均在计时外。每个查询保留两个计时读数，结果占用额外内存，
因此仍非零观测开销。源码、程序、编译参数、原始输出、数据库/WAL 和摘要都有
哈希记录，驱动拒绝缺字段、错误 schema/scope、计数漂移、错误驻留条件和隐藏写入。

ASAN / TSAN 使用 512 条记录、48 次查询、32 次预热、12/128 帧及 1/4 读者的
一次重复矩阵，时间仅作正确性运行记录。ASAN 实际导入运行库；TSAN 已运行真实
竞争/加锁对照并核对运行库符号。编译数据库 32 个条目均有对应检测参数，其中
本工具实际构建 22 个编译单元，另含 10 个未选为构建目标的主工程条目。

原有 **102 个源码/测试/脚本文件**及三配置历史程序哈希保持不变。核心全量测试
沿用此前同一核心版本的验收证据；本轮运行的是新工具的矩阵、协议、完整记录及
双树结构校验，未重跑完整 Linux 套件、长压测或强杀恢复矩阵。
